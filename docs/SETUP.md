## Calendar: iCal links and ICS files only (Cards 242, 248)

Google Calendar was removed from the shipped app (web, exe and APK) in Card 242 and from the web
server in Card 248. Calendar is Atrium's own events plus read-only iCal links (secret addresses) and
imported ICS files. There is no `/api/calendar` route, no Google OAuth, and no calendar env read
anywhere: `VITE_GOOGLE_CALENDAR`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `CALENDAR_TOKEN_ENC_KEY`,
`CALENDAR_PUBLIC_ORIGIN` and `VITE_CALENDAR_API_ORIGIN` do nothing if set.

The full Google Calendar client and server are on the `archive/google-calendar` branch at `2320a4e`.
[RESTORE-GOOGLE-CALENDAR.md](RESTORE-GOOGLE-CALENDAR.md) lists the env names, migrations, OAuth client
settings and steps.

## Server environment (Vercel project "atrium", or `.env.local` for `npm run dev`)

| Name | Required | What it is |
|---|---|---|
| `DATABASE_URL` | no | Postgres connection string (Neon), used by `src/lib/db.ts` / auth and `npm run db:migrate`. Unset → PGLite fallback. |

`migrations/` has no top-level app migrations now (only the opt-in `migrations/auth/`), so
`npm run db:migrate` reports "nothing to do". The calendar SQL moved to
`docs/archive/google-calendar/migrations/` (not applied, not globbed). The calendar tables already in
the database were **not** dropped.

## Android builds on Windows (Card 197)

`tauri android build` links the compiled Rust library (`.so`) into `src-tauri/gen/android/app/src/main/jniLibs/` with a **symlink**. On Windows, creating symlinks needs **Developer Mode** (Settings → System → For developers → Developer Mode: On) or an elevated shell. Without it, the Rust step compiles and then fails while creating the link, and Gradle never packages the library.

- Turn Developer Mode on once, open a new terminal, and rebuild.
- Workaround if you can't: copy the `.so` from `src-tauri/target/<triple>/debug|release/` into the matching `jniLibs/<abi>/` folder, then run `gradlew assemble<Abi>Debug` in `src-tauri/gen/android`.
- macOS and Linux need nothing extra.

Calendar on Android needs Android System WebView 117+ before Card 197; from Card 197 the app targets Chrome/WebView 110 (TypeScript `lib` is ES2023, so newer built-ins such as `Object.groupBy` fail typecheck; use `src/lib/group-by.ts`).

## Android native sources (Card 199)

`src-tauri/gen/android` is generated by `tauri android init` and git-ignored. Hand-written Android code lives in **`src-tauri/android/`** (tracked) and is copied over the generated project by `scripts/android-overlay.mjs`, which `scripts/tauri-before-build.mjs` runs on every Android build (and you can run by hand after `tauri android init`). Edit the tracked copy, never the one in `gen/`.

- `src-tauri/android/MainActivity.kt`: hardware/gesture **Back**. It turns off wry's WebView-history Back (`handleBackNavigation = false`) and calls `window.__atriumBack()` in the page, which closes the nav drawer, then an open sheet, then a dialog. If the page reports nothing was closed, Back falls through to the default (leave the app).
